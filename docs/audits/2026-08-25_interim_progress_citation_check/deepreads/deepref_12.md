## Upgraded summary

- **Bibliography entry:** [12] M. Mazeika et al., "HarmBench: A standardized evaluation framework for automated red teaming and robust refusal," in Proc. ICML, 2024.
- **Repo PDF:** `Sources/[24.1] Mazeika et al. - HarmBench - A standardized evaluation framework for automated red teaming and robust refusal (PMLR v235 version of record).pdf` (primary; extract basis) + `[24.2] ... (author camera-ready).pdf` alternate noted.
- **Publication status:** Peer-reviewed venue printed on the paper's first page: "Proceedings of the 41 st International Conference on Machine Learning, Vienna, Austria. PMLR 235, 2024. Copyright 2024 by the author(s)." (ref_12.txt:75–77).
- **Problem & context:** Automated red teaming "holds substantial promise" but "the field lacks a standardized evaluation framework to rigorously assess new methods" (17–20); prior papers use disparate, rarely overlapping evaluations — at least 9 distinct evaluation pipelines across 10 prior papers with essentially non-overlapping method comparisons (188–193, Table 1 at 216–254) — and evaluations miss three desirable properties the authors name: breadth, comparability, robust metrics (45–48, 325–328).
- **Approach:** HarmBench = a harmful-behavior dataset plus a standardized three-step evaluation pipeline (generate test cases → greedy-decode completions → classifier-score them; 686–704, Figure 3 at 481–483). Dataset: 510 unique harmful behaviors, 400 textual + 110 multimodal (485–486), in four functional categories — standard 200, copyright 100, contextual 100, multimodal 110 (492–495) — and seven semantic categories (Cybercrime & Unauthorized Intrusion … General Harm; 527–531; per-category counts 121/60/100/68/29/101/31 at 1803–1805), with an official validation/test split of 100/410 behaviors (497–500, 1727). Contextual behaviors pair a context string with a behavior referencing it (522–525); a small study found 55%/50%/0% Google-searchability for MaliciousInstruct/AdvBench/HarmBench-contextual respectively (591–596, Table 3 at 1620–1637). Judge setup: ASR = fraction of test cases whose completion elicits the behavior under greedy decoding, scored by a classifier c(x′, y) (286–301); non-copyright behaviors are judged by a Llama 2 13B Chat fine-tuned via multi-round distillation from tuned GPT-4 prompts (678–684, 1814–1893); copyright behaviors use a hashing-based (MinHash) classifier requiring verbatim-ish copyrighted text (1894–1908). Standardized generation length N = 512 tokens (415). Robustness discipline: held-out validation/test classifiers, prequalification sets of refusal-then-comply completions, random benign paragraphs, and unrelated-behavior completions (382–406, Table 5 at 1878–1884: their classifier 95.68/98.0/93.4 vs GPT-4PAIR 89.0/100.0/78.7 etc.). Using it they compare 18 red teaming methods from 12 papers (GCG, GCG-M, GCG-T, PEZ, GBDA, UAT, AP, SFS, ZS, PAIR, TAP, TAP-T, AutoDAN, PAP-top5, Human Jailbreaks, Direct Request for text; PGD, Adversarial Patch, Render Text, Direct Request for multimodal) against 33 LLMs (24 open-source, 9 closed-source) (21–22, 721–828).
- **Key findings:** (with exact anchors)
  - No current attack or defense is uniformly effective: all attacks have low ASR on ≥1 LLM and all LLMs fail against ≥1 attack (Figure 5 discussion 830–842; caption "No model is robust to all attacks, and no attack breaks all models" 663–664).
  - Robustness is independent of model size within families — stable within model families but highly variable across families over six families spanning 7B–70B across four attacks — so training data/procedures matter more than scale (850–871; Figure 6 caption 811–815).
  - ASR is considerably higher on contextual behaviors and relatively low on copyright behaviors, the latter because the hashing classifier requires the copyrighted text to actually appear (858–864; Figure 11 caption 2283–2287).
  - Token-generation budget shifts substring-matching ASR by up to 30% across prior work settings — motivating standardization at N=512 (408–415; Figure 2 caption 367–371).
  - Headline per-method ASRs (Table 7, All Behaviors panel): GCG on Llama 2 7B/13B/70B Chat = 32.5/30.0/37.5 (2348–2350; layout:1601–1603); PAIR = 9.3/15.0/14.5 (2534–2536; layout:1601–1603); AutoDAN = 0.5/0.8/2.8 (2600–2602). White-box suffix attacks (GCG, PEZ, GBDA, UAT, AP, and GCG-M) were not run on closed models ("-" cells; layout:1625), so GPT-4-class numbers exist only for transfer/black-box attacks: GCG-T on GPT-4 0613 = 22.0 and GPT-4 Turbo 1106 = 22.3 (2704–2705; layout:1625); PAIR on GPT-4 0613 = 39.3, GPT-4 Turbo 1106 = 33.0 (2734–2735; layout:1625); AutoDAN not run on any closed model ("-"; layout:1625). Attack averages across all models: GCG 54.3, PAIR 40.7, AutoDAN 52.7 (2698/2740/2762; layout: Average row).
  - R2D2 (Robust Refusal Dynamic Defense, App. A: persistent test cases optimized by GCG during fine-tuning, away loss + toward loss toward a fixed refusal string + SFT loss; 1458, 1507–1519): Zephyr 7B + R2D2 reaches state-of-the-art GCG robustness among model-level defenses, outperforming Llama 2 7B Chat (31.8 → 5.9 %ASR) and Llama 2 13B Chat (30.2 → 5.9) (987–989); on the Table 7 All-Behaviors panel Zephyr 7B = 69.5 vs R2D2 = 5.5 GCG ASR (2365–2366; layout:1601, 1621); training took 16 h on one 8×A100 node (M=500 steps, N=180 persistent test cases, m=5 GCG steps, n=8 per iteration, K=20% reset every L=50 steps) (968–972); MT-Bench 6.0 (R2D2) vs 6.5 (Mistral 7B Instruct v0.2), with full Table 12 row values 7.34/69.4/62.7 (Zephyr Beta), 6.5/69.1/55.7 (Mistral Instruct v0.2), 5.4/62.2/48.5 (Koala 13B), 6.0/5.5/19.1 (Zephyr+R2D2) (963–964; 8435–8461).
  - Judge quality: the distilled Llama 2 13B classifier reaches 94.53% (standard) / 90.5% (contextual) agreement with human labels, average 93.19%, beating GPT-4-based judging (89.8/85.5, avg 88.37) and all other prior classifiers (Table 4, 1659–1692; caption 1639–1641); validation classifier 88.6% vs test classifier 93.2% human agreement (1742–1745).
- **Cited in the report at:** Chapter 1 > 1.1 Background and Motivation, Chapter 2 > 2.1 Trustworthiness and Safety Evaluation (this value is stamped authoritatively later — kept as given).
- **Limitations & caveats:** (the paper's own stated ones)
  - Copyright caveat on the size-independence finding: ASR *increases* with model size on copyright behaviors, plausibly because smaller models cannot produce copyrighted text at all; only non-copyright behaviors separate robustness from capability (871–872, 934–938).
  - R2D2's gains are weakest on attacks dissimilar to its train-time GCG adversary (PAIR, TAP, Stochastic Few-Shot); training against multiple diverse attacks may be needed for generalizable robustness (944–948).
  - Claude and Gemini APIs include non-removable output filters, so their model-level defense robustness cannot be directly measured (2026–2033); GPT-4-class white-box attack cells are absent for the same structural reason (layout:1625).
  - Closed-source attacker/evaluator LLMs in prior methods were replaced with Mixtral 8x7B, which "can reduce their effectiveness" though it cuts cost and enables compute comparisons (1963–1966).
  - Some red teaming methods were excluded outright (Perez et al.'s Supervised/RL methods, ARCA, MasterKey, Shah et al.'s pipeline) for compute or formulation reasons (1969–1975, 1589–1591).
  - Validation-split category proportions do not exactly match final semantic categories because an earlier category set was used for stratification (1730–1732).
  - The metric itself is imperfect: 51 validation-classifier vs 41 test-classifier errors on 600 human-labeled completions, with only 26 errors shared (1742–1745); greedy decoding is an assumption inherited from prior work, not validated (289–291).
  - The behavior set is hand-curated; automating behavior selection remains open and "may be challenging or undesirable" (X-risk sheet Q7/F.3, 8862–8864, 8903–8906).
  - The searchability experiment is a 20-behavior-per-dataset, single-author exercise acknowledged as "only a lower bound" (Table 3 caption 1620–1626; method 591–596).
  - Zephyr 7B + R2D2 omits the DPO stage, so it "is not exactly comparable" to Zephyr 7B Beta (Table 12 caption, 8430–8433).
- **Relevance to this FYP:** This is the source benchmark and judge for the repo's primary safety metric. The paper directly supports the project's decision to score HarmBench ASR with the official open-weight classifier (`cais/HarmBench-Llama-2-13b-cls`, decision D16): HarmBench's own argument is that a static open-source judge avoids API drift (691–694) and that substring/refusal-string metrics are unstable to generation length (up to 30% ASR swing, 408–415) — exactly the mechanism behind this repo's finding that the v2 regex over-counts ASR relative to the judge. Its standardized greedy decoding (290–291) matches the repo's temperature-0 protocol, and its N=512-token convergence standard (415) matches the primary 512-token results tree (D41) — the paper gives citable grounds for both choices. Its held-out validation/test classifier discipline (1714–1745) parallels the repo's judge-validation layering (classifier + gpt-4o + LlamaGuard + human gold sets). Substantively, "no attack or defense is uniformly effective" (830–842) and "robustness is independent of model size" (850–871) frame the FYP question: if even fp16 instruction-tuned pairs vary mainly by training procedure, then quantization-pair deltas must be interpreted against capability degradation, not assumed alignment shifts. Caveat when citing: the 31.8→5.9 / 30.2→5.9 R2D2 numbers are prose figures whose exact panel is not restated (they differ from Table 7's 69.5→5.5 and Table 12's 69.4→5.5 GCG columns), so quote them as stated in §5.2 rather than re-deriving them from the tables.
